# 연금플러스 개발 전 준비

> 아래 빈칸을 팀이 함께 채운 뒤 개발을 시작합니다.

## 1. 서비스 기준

> **작성 팁:** 한 항목을 한 문장으로 작성합니다. 기능 설명보다 `누가, 어떤 상황에서, 무엇을 해결하는지`를 적습니다.

| 항목 | 결정 |
|---|---|
| 서비스 한 줄 소개 | 예: 연금을 옮기거나 받을 때 결과를 미리 보여주는 서비스 |
| 핵심 사용자 | 예: 연금 이전을 고민하는 일반 고객 |
| 가장 중요한 문제 | 예: 이전 중 현재 단계와 매매 제한 기간을 알기 어렵다 |
| 핵심 사용자 흐름 | 예: 계좌 확인 → 이전 영향 확인 → 진행 현황 확인 |

## 2. 구현 화면

> **작성 팁:** 실제로 개발할 화면만 체크합니다. 새로운 화면이 필요하면 기존 화면의 모달이나 카드로 처리할 수 있는지 먼저 확인합니다.

- [ ] 홈
- [ ] 이전 계좌 확인
- [ ] 이전 전 확인
- [ ] 이관 현황판
- [ ] 인출 조건 입력
- [ ] 인출 결과

### 이번에 구현하지 않는 것

- 실제 계좌·금융기관 연결
- 로그인·회원가입
- 실제 이체·출금
- 타명의·상속 상세 흐름

## 3. 역할

> **작성 팁:** 한 작업의 담당자는 한 명만 정합니다. 담당자는 구현뿐 아니라 화면 확인과 오류 수정까지 책임집니다.

| 역할 | 담당자 | 주요 업무 |
|---|---|---|
| A · 공통/통합 |  | 프로젝트 설정, 계산, 통합, 배포 |
| B · 기능1 |  | 이전 계좌 확인, 이관 현황판 |
| C · 기능2 |  | 인출 입력, 한도, 인출 결과 |
