# 연금플러스 개발 전 준비

> 기존 PRD와 예상 프로토타입을 바탕으로 정리한 회의 초안입니다. 팀 회의에서 내용을 확인한 뒤 체크 표시를 완료합니다.

## 1. 서비스 기준

> **작성 팁:** 한 항목을 한 문장으로 작성합니다. 기능 설명보다 `누가, 어떤 상황에서, 무엇을 해결하는지`를 적습니다.

| 항목 | 결정 |
|---|---|
| 서비스 한 줄 소개 | 연금계좌를 옮기거나 연금을 인출하기 전에 진행 과정과 예상 결과를 미리 보여주는 서비스 |
| 핵심 사용자 | PB의 도움 없이 연금계좌 이전 과정을 직접 확인해야 하는 일반 고객 |
| 가장 중요한 문제 | 사용자는 현재 처리 단계와 매매 제한 기간을 알기 어렵다 |
| 핵심 사용자 흐름 | 이전할 계좌·종목 확인 → 이전 시 제한 사항 확인 → 이관 조건 최종 확인 → 단계별 진행 현황 확인 |

## 2. 구현 화면

> **작성 팁:** 실제로 개발할 화면만 체크합니다. 새로운 화면이 필요하면 기존 화면의 모달이나 카드로 처리할 수 있는지 먼저 확인합니다.

- [ ] 홈
- [ ] 로그인 — 시연용 화면
- [ ] 회원가입 — 시연용 화면
- [ ] 이전 계좌 확인
- [ ] 이전 전 확인
- [ ] 이관 현황판 — 핵심 흐름
- [ ] 인출 조건 입력 — 보조 흐름
- [ ] 인출 결과 — 보조 흐름

> 위 8개 화면을 기본안으로 두고 회의에서 최종 확정합니다. 로그인·회원가입은 실제 인증 없이 화면과 홈 진입만 구현합니다.

### 이번에 구현하지 않는 것

- 실제 계좌·금융기관 연결
- 실제 계정 생성·본인 인증·비밀번호 찾기
- 실제 이체·출금
- 타명의·상속 상세 흐름

## 3. 역할

> **작성 팁:** 한 작업의 담당자는 한 명만 정합니다. 담당자는 구현뿐 아니라 화면 확인과 오류 수정까지 책임집니다.

| 역할 | 담당자 | 주요 업무 |
|---|---|---|
| A · 공통/통합 | 양승연 | 프로젝트 설정, 시연용 로그인·회원가입 UI, 문서·추적표, 코드 통합, QA, 배포, README·발표자료 |
| B · 기능1 | 회의에서 결정 | 이전 계좌 확인, 이전 전 확인, 이관 현황판 |
| C · 기능2 | 회의에서 결정 | 인출 조건 입력, 한도·계산, 인출 결과 |

> 기능1·2 담당자는 담당 UI뿐 아니라 mock 연결, 오류 수정, 빌드 확인까지 책임집니다. 기능2 계산값은 공통/통합 담당자가 별도로 교차 검증합니다.

## 4. 시연용 데이터

- 기능1과 기능2의 시연용 데이터는 각 담당자가 별도로 관리합니다.
- 각 기능 안에서는 화면이 바뀌어도 계좌·금액·계산 결과가 서로 맞아야 합니다.
- 기존 PRD와 예상 프로토타입의 값을 우선 참고합니다.
- 화면에는 `시연용 데이터`를 표시하고, 실제 마이데이터 연동으로 오해할 표현을 사용하지 않습니다.
