## 1. 역기획 이후 먼저 결정할 부분

역기획 결과를 그대로 구현하면 기존 증권사의 화면 개선안에 머물 수 있다. 개발을 시작하기 전에 아래 내용을 팀이 함께 결정한다.

### 1.1 서비스 정체성

- 우리는 KB증권의 개선안을 만드는가, 독립적인 연금 서비스를 만드는가?
- 특정 증권사에 속하지 않는 서비스라면 사용자가 우리 서비스를 따로 써야 하는 이유는 무엇인가?
- 기능1과 기능2를 하나의 서비스로 묶는 공통 가치는 무엇인가?

### 1.2 해결할 핵심 문제

- 연금을 옮길 때 진행 상황과 제한 기간을 알기 어렵다.
- 연금을 받을 때 어떤 재원부터 빠지고 세금이 얼마나 발생하는지 알기 어렵다.
- 두 문제 중 MVP에서 더 중요하게 검증할 문제는 무엇인가?

### 1.3 대표 사용자

- 첫 MVP가 가장 먼저 도울 사용자는 누구인가?
- 연금을 옮기려는 사용자와 받으려는 사용자를 하나의 대표 사용자로 볼 수 있는가?
- 두 사용자가 다르다면 기능별 가설을 따로 검증할 것인가?

### 1.4 실제 구현과 모의 구현의 경계

- 화면 이동, 입력, 계산은 실제로 작동시킨다.
- 계좌, 종목, 이관 상태는 모의 데이터를 사용한다.
- 실제 금융기관 연동, 인증, 이체와 출금 실행은 구현하지 않는다.
- 모든 관련 화면에 `시연용 데이터` 또는 `모의계산`을 표시한다.

### 1.5 MVP 범위

- 4일 안에 반드시 완성할 사용자 흐름은 무엇인가?
- 어떤 예외 상태까지 보여줄 것인가?
- 일정이 늦어지면 가장 먼저 제외할 기능은 무엇인가?
- 기능2에서 지원할 계산 조건을 어디까지 제한할 것인가?

### 1.6 성공 판단 기준

- 사용자가 현재 이관 단계와 완료 예상 기간을 찾을 수 있는가?
- 사용자가 제한되는 업무와 해제 시점을 이해할 수 있는가?
- 사용자가 인출 재원의 차감 순서를 설명할 수 있는가?
- 사용자가 예상 세금과 실수령액을 찾을 수 있는가?
- 두 기능이 하나의 서비스에 있는 이유를 이해하는가?

### 팀 결정 기록

| 결정 항목 | 최종 결정 |
|---|---|
| 서비스 한 줄 소개 | 회의 후 작성 |
| 대표 사용자 | 회의 후 작성 |
| 가장 중요한 문제 | 회의 후 작성 |
| 기능1 필수 범위 | 회의 후 작성 |
| 기능2 필수 범위 | 회의 후 작성 |
| 가장 먼저 제외할 기능 | 회의 후 작성 |
| MVP 성공 기준 | 회의 후 작성 |

## 2. 추천 포지셔닝과 차별점

> 아래 내용은 팀 논의용 제안이며 확정안이 아니다.

### 추천 포지셔닝

기존 표현:

> 연금 이전 현황과 인출순서를 보여주는 서비스

추천 표현:

> 연금을 옮기거나 받을 때, 선택에 따른 손실과 세금을 미리 비교해 주는 연금 의사결정 도구

추천 한 줄 소개:

> 연금의 중요한 순간, 선택하기 전에 결과부터 확인하세요.

### 공통 가치

| 사용 시점 | 사용자의 질문 | 서비스가 제공할 답 |
|---|---|---|
| 연금을 옮길 때 | 지금 옮겨도 될까? | 이전 가능 여부, 예상 손익, 잠금 기간, 병목 요인 |
| 연금을 받을 때 | 지금 얼마를 받는 게 좋을까? | 차감 순서, 한도 초과액, 예상 세금, 실수령액 |

두 기능을 다음 질문으로 연결한다.

> 지금 이 선택을 하면 내 돈에 어떤 일이 생기는가?

### MVP 차별점 제안

새로운 대형 기능 대신 기존 결과에 간단한 비교를 추가한다.

- 기능1: `오늘 바로 이전`과 `병목 종목 정리 후 이전`의 예상 손익·기간 비교
- 기능2: `한도 내 인출`과 `요청 금액 전부 인출`의 예상 세금·실수령액 비교

이를 통해 단순 조회 화면에서 선택 전 의사결정 도구로 확장한다.

## 3. MVP 구현 범위

### 기능1 · 이수관 현황판

1. 이전 계좌와 보유 종목 확인
2. 그대로 이전·매도 필요 종목 구분
3. 예상 손익과 잠금 기간 확인
4. 5단계 이관 현황판
5. 현재 단계, 처리 기관, 완료 예상 기간 표시
6. 제한 업무와 예상 해제 시점 표시
7. 정상 진행·고객 확인 필요·완료 상태

### 기능2 · 인출순서 시뮬레이터

1. 샘플 계좌와 인출 희망 금액 입력
2. 연금수령한도와 초과분 표시
3. 3단계 재원 차감 순서 표시
4. 재원별 예상 세금 표시
5. 총 예상 세금과 실수령액 표시
6. 계산 근거, 기준일, 모의계산 문구 표시

### 제외 범위

- 실제 계좌 연결과 금융기관 API
- 회원가입, 로그인, 본인 인증
- 실제 이체·출금·주문 실행
- 데이터베이스와 관리자 화면
- 타명의·상속 상세 흐름
- 모든 세무·이관 예외 조건

## 4. 역할 분담

역할은 팀원 이름을 정한 뒤 배정한다.

### 역할 A · 기반과 계산

- 프로젝트와 공통 레이아웃 설정
- 공통 타입과 화면 이동 구성
- 기능2 계산 함수와 테스트
- 전체 통합 확인과 배포

### 역할 B · 기능1

- 이전 계좌 확인부터 이관 완료까지 기능1 전체
- 기능1 모의 데이터와 상태 전환
- 기능1 자체 점검

### 역할 C · 기능2 화면

- 인출 조건 입력부터 결과까지 기능2 화면 전체
- 역할 A의 계산 함수 연결
- 기능2 자체 점검

각 역할은 담당 기능의 구현, 확인, 충돌과 오류 수정까지 책임진다.

## 7. 완료 기준

- 배포 URL에서 기능1과 기능2를 끝까지 체험할 수 있다.
- 현재 이관 단계, 완료 예상 기간, 제한 업무를 확인할 수 있다.
- 인출 재원의 차감 순서, 예상 세금, 실수령액을 확인할 수 있다.
- 대표 계산값과 테스트 결과가 일치한다.
- 모바일 360px 화면에서 주요 기능을 사용할 수 있다.
- 모든 모의 데이터와 계산이 명확하게 표시된다.
- 새로고침과 주요 버튼에서 치명적인 오류가 발생하지 않는다.

## 8. 주요 리스크

| 리스크 | 대응 |
|---|---|
| 구현 범위 증가 | Day 2 이후 신규 기능을 추가하지 않는다 |
| 계산 오류 | 기준값과 자동 테스트로 확인한다 |
| 작업 충돌 | 담당 폴더를 분리하고 매일 `dev`에 통합한다 |
| AI의 과도한 변경 | 한 번에 한 화면·함수만 요청하고 변경 범위를 지정한다 |
| 실제 금융 기능으로 오인 | 모의 데이터·모의계산 표시와 면책 문구를 둔다 |
