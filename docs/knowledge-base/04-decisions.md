# 의사결정 기록

| ID | 결정 | 근거 | 상태 | 재검토 조건 |
|---|---|---|---|---|
| DEC-001 | 기존 상세 PRD·SRS를 유지하고 MVP 문서를 별도로 작성 | 원본 근거를 보존하면서 4일 범위로 축약 | 확정 | 전체 제품 개발 착수 시 |
| DEC-002 | 실제 금융 연동 대신 시연용 데이터를 사용 | 핵심 UX 검증에 집중하고 개인정보·인증 범위를 제외 | 확정 | 실제 연동 검증이 프로젝트 목표가 될 때 |
| DEC-003 | Vite + React 기반 모바일 웹으로 구현 | 서버·DB가 필요 없는 클라이언트형 MVP | 확정 | 서버 기능이 필수 범위에 포함될 때 |
| DEC-004 | 핵심 사용자와 Happy Path를 각각 1개로 제한 | 3명·4일 범위와 2분 데모 기준 | 확정 | 기존 기능을 같은 크기로 제외할 때 |
| DEC-005 | 팀원 부재 상황에서 Product·Integration 담당자가 MVP 범위를 우선 확정 | 4일 일정 지연 방지 | 확정 | 팀원이 범위 변경을 요청할 때 같은 크기의 기존 범위와 교환 |

## 기록 규칙

결정이 바뀌면 기존 행을 삭제하지 않고 상태와 재검토 이유를 갱신합니다. 구현에 영향을 준 결정은 SRS Requirement와 GitHub Issue에 연결합니다.
