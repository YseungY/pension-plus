# 연금플러스 Master Deck

> 16페이지 발표 원고 · 8분 발표 + 4분 질의 · 핵심 흐름 데모 2분 이내  
> `---`로 구분된 각 구간이 슬라이드 1장입니다. `[추후 입력]`은 구현·배포·QA 후 교체합니다.

## 1. 기다리는 연금 이전, 이제는 진행 상황이 보입니다

### 연금플러스

연금계좌 이관 진행 조회 · 인출순서 모의계산 MVP

페이스메이커 · 김동건 · 유고은 · 양승연

**화면에 넣을 한 문장**

> 처리 속도를 약속하는 대신, 지금 어디까지 왔는지 보여줍니다.

**권장 시각자료:** 이관 현황판 핵심 화면 1장 또는 서비스 로고

**발표자 노트:** 연금플러스는 실제 금융 서비스가 아니라 사용자 가설을 검증하는 모바일 웹 MVP입니다.

## 2. 사용자는 신청 이후의 시간을 알 수 없습니다

### 핵심 사용자

PB의 도움 없이 연금계좌 이전 과정을 직접 확인해야 하는 일반 고객

### 발견한 문제

- 현재 화면은 처리 상태를 `신청중` 한 줄로 보여줍니다.
- 사용자는 지금 어느 기관에서 처리 중인지 알기 어렵습니다.
- 매매 제한이 언제 시작되고 풀리는지도 확인하기 어렵습니다.

**핵심 판단**

> 줄일 수 없는 처리 시간을, 이해할 수 있는 대기 시간으로 바꿔야 합니다.

**권장 시각자료:** 기존 화면의 `신청중` 영역과 개선 화면 비교

**발표자 노트:** 속도 개선이 아니라 진행 가시성 개선이 이번 프로젝트의 중심 가설입니다.

**근거:** `docs/team/product/PRD_원본상세.md` §1·§4, `docs/submission/knowledge-base/01-product-context.md`

## 3. 기존 기획을 다시 만들지 않고 MVP에 필요한 것만 남겼습니다

### 재사용

- 상세 PRD 66개 요구사항
- 12화면 예상 프로토타입
- 서비스 역기획서와 디자인 시스템
- 상세 SRS와 계산 규칙

### 이번 MVP로 축소

- 핵심 Requirement 12개
- 핵심 제품 화면 6개
- 시연용 로그인·회원가입 화면 2개
- 중요 예외 2개

### 제외

- 실제 계정·인증·세션
- 서버·데이터베이스
- 실제 마이데이터·금융기관 API
- 실제 이체·출금·주문

**권장 시각자료:** `66개 → 12개`, `12개 핵심 후보 → 6개 제품 화면 + 2개 시연 화면` 축약 그래픽

**발표자 노트:** 로그인과 회원가입은 제출 시연 흐름을 위한 UI만 제공하며 실제 계정은 생성하지 않습니다.

**근거:** `docs/submission/PRD_MVP.md`, `docs/team/start/개발전_준비.md`

## 4. 사람과 AI가 같은 근거를 읽도록 Knowledge Base를 만들었습니다

### 다섯 개의 짧은 지식 경로

1. 제품 맥락 — 누구의 어떤 문제인가
2. 리서치 근거 — 왜 이 문제가 중요한가
3. 도메인·기술 메모 — 무엇을 지켜야 하는가
4. 의사결정 기록 — 무엇을 선택하고 제외했는가
5. 용어집 — 같은 단어를 같은 뜻으로 쓰는가

### 핵심 근거가 만든 결정

- 한 줄 상태 표시 → 단계별 이관 현황판
- 법정 3층 인출순서 → 추천이 아닌 결정론적 모의계산
- 4일 일정과 개인정보 위험 → 실제 API 대신 로컬 시연용 데이터

**권장 시각자료:** `00-index.md`를 중심으로 5개 문서가 연결된 단순 구조

**발표자 노트:** 전체 자료를 AI에 반복 입력하지 않고 KB 인덱스에서 필요한 근거만 선택하게 했습니다.

**근거:** `docs/submission/knowledge-base/00-index.md`

## 5. 핵심 흐름은 계좌 확인에서 진행 현황까지 끊기지 않습니다

### 기능1 · 발표 중심 흐름

타사 퇴직연금 가져오기
→ 보유 종목 확인
→ 이전 시 제한 사항 확인
→ 이관 조건 최종 확인
→ 단계별 진행 현황 확인

### 기능2 · 보조 흐름

연금저축 관리 → 연금 외 수령 조건 확인
→ 법정 차감 순서 확인
→ 예상 세금과 실수령액 확인

**성공 기준**

- 핵심 흐름을 2분 이내 시연
- 모바일 360px에서 중단 없이 이동
- 모든 mock 화면에 `시연용 데이터` 표시
- 계산 결과에 `모의계산`과 한계 표시

**권장 시각자료:** 핵심 흐름 5단계 화살표

**근거:** `docs/submission/PRD_MVP.md` §3·§5

## 6. SRS는 화면 설명을 판정 가능한 조건으로 바꿨습니다

### 핵심 Requirement

- FR-003 — 종목을 `그대로 옮김 / 팔아야 함 / 판정 불가`로 분류
- FR-004 — 잠금 구간을 시작 시각·해제 밴드·영업일 수로 표시
- FR-006~009 — 단계·확정/추정·완료 밴드·고객 확인 예외 표시
- FR-010~012 — 한도·평가금액 초과·3층 인출 결과 계산

### 중요 예외

- 고객 확인이 필요한 이관 상태
- 인출금액이 평가금액을 초과한 상태

### 비기능 조건

- 모바일 360px 우선
- 완료일은 단일 날짜가 아닌 기간으로 표시
- 계산식과 화면 컴포넌트 분리
- `any` 사용 금지

**권장 시각자료:** Requirement 1개의 `입력 → 규칙 → 출력 → AC` 예시

**근거:** `docs/submission/SRS_MVP.md`

## 10. 기능1은 사용자가 지금 어디에 있는지 먼저 보여줍니다

### 화면에서 답하는 네 가지 질문

1. 어떤 계좌와 종목을 옮기는가?
2. 그대로 옮길 수 있는 종목은 무엇인가?
3. 지금 제한되는 업무는 무엇인가?
4. 언제쯤 다음 단계로 넘어가는가?

### 핵심 UX

- 종목별 이전 가능 여부
- 매매 제한 시작과 해제 예상 기간
- 현재 단계 강조
- 확정 정보와 추정 정보 구분
- 고객 확인이 필요한 경우 다음 행동 표시

**권장 시각자료:** `[기능1 최종 화면 캡처 입력]`

**발표자 노트:** 완료일을 단정하지 않고 기간으로 보여주는 것이 신뢰 설계의 핵심입니다.

## 11. 기능2는 세금보다 먼저 차감 순서를 이해하게 합니다

### 입력

- 계좌 평가금액

- 추천·자문형 문구 사용 금지
- 계산 기준과 적용값 공개
- `모의계산` 및 실제 결과 차이 안내

**권장 시각자료:** `[기능2 입력·결과 화면 캡처 입력]`

**발표자 노트:** 사용자가 순서를 선택하는 기능이 아니라 법정 순서를 설명하는 계산 도구입니다.

## 15. 이번 MVP는 연동이 아니라 설명 방식의 가능성을 검증합니다

### 남은 한계

- 실제 마이데이터·예탁결제원 연동을 검증하지 못했습니다.
- 실제 상품별 처리 기간과 잠금 정책을 검증하지 못했습니다.
- 실제 인증·세션·개인정보 처리는 구현하지 않았습니다.
- 계산 결과는 시연용이며 실제 원천징수 결과와 다를 수 있습니다.

### 다음 개발 순서

1. 사용자 테스트로 단계·제한 문구 개선
2. 실제 데이터 계약과 API Adapter 정의
3. 상품별 완료 기간 근거 검증
4. 법무·컴플라이언스 검토
5. 실제 인증·로그·개인정보 보호 설계
